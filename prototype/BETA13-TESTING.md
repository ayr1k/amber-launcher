# AMBER Beta 1.3 测试说明

版本：1.0.0-beta.4。以 GitHub 预发布方式提供。微软真实认证验收继续延后。

## 安装与数据

运行 AMBER-1.0.0-beta.4-Setup-x64.exe。先退出 AMBER 与 Minecraft，可覆盖原 AMBER 程序目录；不要安装到游戏数据目录。安装器沿用旧程序备份、目录检查与卸载保留数据策略。安装包未签名，SHA256SUMS.txt 用于核对发布附件。

## 建议先测试这些路径

1. 设置 → 外观与背景：切换浅 / 深色、直角 / 圆角、13–18 号字及信息密度。展开各选择列表，使用方向键 / Enter / Esc / Tab；在长列表搜索，检查没有结果时的提示。
2. 创建实例 → 选择版本 → 配置组件：在加载器长列表搜索并选择发行版；小窗口下检查列表不越界，Esc 只关闭列表，原弹窗仍在。
3. 启动页：实例 A 的启动选项保存独立内存，实例 B 使用全局默认。更改设置中的默认内存，检查只有 B 跟随；重启检查 A 保留独立值。账号选择同样按实例保存，移除已选账号后应提示重新选择。
4. 内容下载：输入关键词并改变分类 / 排序，切换第二页，向下浏览后打开项目再返回；离开到设置后返回商城，应保留状态。切换实例不应沿用另一个实例的兼容结果。
5. 已安装内容：勾选多个文件，先预览“批量停用”。仅选择被依赖的前置模组时应阻止；把使用它的模组一起选中后应允许。已经符合目标状态的文件显示跳过。
6. 在可丢弃的测试实例上验证批量启用、停用、移除及恢复。完成后到“模组更新与恢复 → 刷新恢复记录”确认恢复；恢复不回退存档或配置。
7. 模组批量操作受当前游戏 / 下载状态保护；任务中心可查看每项结果。失败时保留错误和恢复记录，不应显示全部完成。
8. 设置搜索“内存”“圆角”“位置”；恢复当前组默认值，检查其他组不变化。数据位置操作仍需明确选择目标。
9. 任务中心：未完成完整安装只显示一张主任务卡，阶段记录可展开；检查“需要处理”“进行中”“已完成”的空状态和下一步入口。

## 验证与限制

- 后端测试使用隔离临时实例，覆盖整组依赖检查、显式例外、冲突、同名文件、外部修改、过期状态、取消 / 失败回滚、恢复和实例设置持久化。
- 浏览器布局验证使用明确标识的合成样例，覆盖深浅主题、直角圆角、最小桌面窗口和大字体。样例不执行真实下载或游戏启动。
- 打包程序使用独立 smoke-data 自检，检查前端载入、桌面 IPC、背景资源及系统加密。没有安装到用户现有游戏目录。
- 不把自动化或布局样例视为真实微软认证、所有加载器组合、所有模组组合或真实断电测试。手动导入 / 未声明的依赖仍可能在运行时发生冲突。
- 商城浏览状态保留在本次应用会话内，不是跨重启持久化；实例账号和内存独立设置会保存到磁盘。
- 恢复副本与原文件在同一数据盘，不代替异盘备份。恢复仅在该次操作后的内容清单未发生变化时可直接执行。
